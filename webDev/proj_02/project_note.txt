================================================================================
                    🗄️ PRISMA ORM SETUP GUIDE FOR Node.js
================================================================================
Complete reference for setting up Prisma in any Node.js/Express backend project

📦 VERSION INFO
================================================================================
Prisma Version: 7.4.2
Node.js: v14+
Database: MySQL (compatible with PostgreSQL, SQLite, MongoDB, etc.)

🚀 STEP 1: INSTALL DEPENDENCIES
================================================================================
npm install @prisma/client
npm install -D prisma
npm install -D ts-node typescript
npm install dotenv
npm install -D @types/node

📝 STEP 2: INITIALIZE PRISMA
================================================================================
npx prisma init

This creates:
  ✅ .env file (for DATABASE_URL)
  ✅ prisma/schema.prisma (database schema)
  ✅ prisma/migrations/ (migration history folder)

⚙️ STEP 3: CONFIGURE .env
================================================================================
DATABASE_URL=mysql://username:password@localhost:3306/database_name

Example MySQL Connection String:
DATABASE_URL=mysql://root:webdevprogrammer@localhost:3306/pubmarket_db

⚠️ IMPORTANT NOTES:
  • Never commit .env to git - add to .gitignore
  • Use strong passwords in production
  • Ensure MySQL server is running on localhost:3306
  • Database must exist or let Prisma create it

🏗️ STEP 4: DEFINE DATABASE SCHEMA
================================================================================
Edit prisma/schema.prisma:

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "mysql"    // Change to PostgreSQL, SQLite, etc. as needed
}

// Model Example:
model User {
  id               Int             @id @default(autoincrement())
  username         String?         @unique
  email            String?         @unique
  password         String?
  createdAt        DateTime        @default(now())
  updatedAt        DateTime        @updatedAt
  
  posts            Post[]          // 1-to-many relation
  
  @@map("users")      // Map to database table name
}

model Post {
  id      Int     @id @default(autoincrement())
  title   String
  userId  Int
  
  user    User    @relation(fields: [userId], references: [id], onDelete: Cascade)
}

KEY FIELD DIRECTIVES:
  @id                 - Primary key
  @unique             - Unique constraint
  @default(value)     - Default value
  @default(now())     - Current timestamp
  @updatedAt          - Auto-update on change
  @map("name")        - Database column name mapping
  @@map("table_name") - Database table name mapping

RELATIONSHIPS:
  One-to-Many:  parent Post[] on child User
  Many-to-One:  child User @relation(...) on parent
  Cascade:      onDelete: Cascade (delete children when parent deleted)

📊 STEP 5: PUSH SCHEMA TO DATABASE
================================================================================
npx prisma db push

This:
  ✅ Creates tables in MySQL based on schema.prisma
  ✅ No migration file created (for development)
  ✅ Generates Prisma Client automatically

🔧 STEP 6: GENERATE PRISMA CLIENT (For Prisma v7+)
================================================================================
Set DATABASE_URL environment variable, then:

npx prisma generate

OR with dotenv (recommended):
$env:DATABASE_URL="mysql://root:password@localhost:3306/db"; npx prisma generate

🛑 COMMON ERRORS & FIXES
================================================================================
ERROR: "PrismaClient needs to be constructed with a non-empty, valid PrismaClientOptions"
FIX: 
  1. Ensure DATABASE_URL is set in .env
  2. Remove prisma.config.ts from root (Prisma v7 incompatibility)
  3. Run: npx prisma generate

ERROR: "datasource url property is no longer supported"
FIX: 
  1. Remove 'url' from datasource in schema.prisma
  2. Set DATABASE_URL in environment
  3. Update schema to only have 'provider'

ERROR: "Cannot find module @prisma/client"
FIX:
  1. Run: npm install @prisma/client
  2. Run: npx prisma generate
  3. Restart server/IDE

📁 STEP 7: CREATE PRISMA CLIENT INSTANCE
================================================================================
File: src/lib/prisma.ts

import { PrismaClient } from "@prisma/client";

⚠️ IMPORTANT: Do NOT create new PrismaClient() multiple times!
Use singleton pattern (above) to avoid connection pool exhaustion.

🔌 STEP 8: INTEGRATE WITH EXPRESS SERVER
================================================================================
File: src/server.ts

import express from "express";
import prisma from "./lib/prisma";
import dotenv from "dotenv";

dotenv.config();

const app = express();
app.use(express.json());

// CREATE
app.post("/api/users", async (req, res) => {
  try {
    const user = await prisma.user.create({
      data: {
        username: req.body.username,
        email: req.body.email,
        password: req.body.password,
      },
    });
    res.status(201).json({ status: "success", data: user });
  } catch (error: any) {
    res.status(500).json({ status: "error", message: error.message });
  }
});

// READ ALL
app.get("/api/users", async (req, res) => {
  try {
    const users = await prisma.user.findMany({
      include: { posts: true },    // Include relations
      orderBy: { createdAt: "desc" },
    });
    res.json({ status: "success", data: users });
  } catch (error: any) {
    res.status(500).json({ status: "error", message: error.message });
  }
});

// READ ONE
app.get("/api/users/:id", async (req, res) => {
  try {
    const user = await prisma.user.findUnique({
      where: { id: parseInt(req.params.id) },
      include: { posts: true },
    });
    if (!user) return res.status(404).json({ status: "error", message: "Not found" });
    res.json({ status: "success", data: user });
  } catch (error: any) {
    res.status(500).json({ status: "error", message: error.message });
  }
});

// UPDATE
app.put("/api/users/:id", async (req, res) => {
  try {
    const user = await prisma.user.update({
      where: { id: parseInt(req.params.id) },
      data: req.body,
    });
    res.json({ status: "success", data: user });
  } catch (error: any) {
    res.status(500).json({ status: "error", message: error.message });
  }
});

// DELETE
app.delete("/api/users/:id", async (req, res) => {
  try {
    const user = await prisma.user.delete({
      where: { id: parseInt(req.params.id) },
    });
    res.json({ status: "success", message: "User deleted", data: user });
  } catch (error: any) {
    res.status(500).json({ status: "error", message: error.message });
  }
});

app.listen(5000, () => console.log("✅ Server running on port 5000"));

🔍 COMMON PRISMA QUERIES
================================================================================

// Create with relations
prisma.user.create({
  data: {
    username: "john",
    posts: {
      create: [
        { title: "Post 1" },
        { title: "Post 2" },
      ],
    },
  },
  include: { posts: true },
});

// Find with filtering & pagination
prisma.user.findMany({
  where: {
    email: { contains: "gmail" },
    createdAt: { gte: new Date("2024-01-01") },
  },
  select: { id: true, username: true },  // Select specific fields
  orderBy: { createdAt: "desc" },
  skip: 0,
  take: 10,  // Pagination: 10 items per page
});

// Update with relations
prisma.user.update({
  where: { id: 1 },
  data: {
    username: "jane",
    posts: {
      disconnect: { id: 2 },           // Remove relation
      connect: { id: 3 },              // Add relation
      create: { title: "New Post" },   // Create new related item
    },
  },
  include: { posts: true },
});

// Delete with cascade
prisma.user.delete({
  where: { id: 1 },
  // If schema has onDelete: Cascade, related posts auto-delete
});

// Aggregate queries
await prisma.post.aggregate({
  _count: true,
  _avg: { userId: true },
});

// Raw queries (use with caution)
await prisma.$queryRaw`SELECT * FROM users WHERE id = ${userId}`;

📝 BEST PRACTICES
================================================================================
✅ DO:
  • Use .env and .env.example files
  • Create singleton PrismaClient instance
  • Use include/select to prevent N+1 queries
  • Hash passwords before storing (use bcrypt)
  • Handle errors in try-catch blocks
  • Use transactions for multiple related operations
  • Validate input before passing to Prisma

❌ DON'T:
  • Create new PrismaClient() on every request
  • Expose DATABASE_URL in code
  • Skip password hashing
  • Use raw queries without escaping
  • Leave console.logs in production
  • Forget to disconnect prisma on app shutdown

🔐 STEP 9: CONNECTING TO BACKEND API
================================================================================

FILE: app/lib/api.ts (Axios setup)

import axios from "axios";

const API_URL = process.env.NEXT_PUBLIC_API_URL || "http://localhost:5000";

const apiClient = axios.create({
  baseURL: API_URL,
  headers: {
    "Content-Type": "application/json",
  },
});

// Add token to all requests
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem("authToken");
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// Handle 401 errors
apiClient.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem("authToken");
      window.location.href = "/auth/login";
    }
    return Promise.reject(error);
  }
);

export default apiClient;

USAGE IN COMPONENTS:
"use client";

import { useState, useEffect } from "react";
import apiClient from "@/lib/api";

export default function UsersList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    apiClient
      .get("/api/users")
      .then((res) => setUsers(res.data.data))
      .catch((err) => console.error(err))
      .finally(() => setLoading(false));
  }, []);

  if (loading) return <p>Loading...</p>;

  return users.map(user => <div key={user.id}>{user.username}</div>);
}

✅ BEST PRACTICES
================================================================================
✅ DO:
  • Use "use client" sparingly (only when needed for interactivity)
  • Keep server components as default for better performance
  • Use Image component (next/image) for optimized images
  • Store auth tokens in httpOnly cookies (not localStorage for sensitive data)
  • Pre-fetch critical data with fetch() in server components
  • Use SWR/React Query for client-side data
  • Implement error boundaries for error handling
  • Use middleware for auth protection
  • Optimize images (compress, use WebP)
  • Monitor Core Web Vitals in production

❌ DON'T:
  • Don't make API calls in server component renders (use fetch)
  • Don't use useState in server components
  • Don't expose secrets in environment variables (use NEXT_PUBLIC_ carefully)
  • Don't forget await on async params in dynamic routes (Next.js 16)
  • Don't use console.log in production (use proper logging)
  • Don't commit .env.local file
  • Don't import heavy libraries in layout.tsx
  • Don't create new API client instances per request

🆘 COMMON ISSUES & FIXES

ISSUE: "Cannot find module '@/components/Button'"
FIX: Check tsconfig.json paths configuration matches actual file location

ISSUE: "hydration mismatch" – Server and client render different content
FIX: Use "use client" on components with useState/useEffect
     Add proper loading states to avoid mismatches

ISSUE: "Port 3000 is already in use"
FIX: npm run dev -- -p 3001 (use different port)
     Or kill process: lsof -ti:3000 | xargs kill -9

ISSUE: Build fails with "image optimization error"
FIX: Check remote image domains in next.config.ts
     Or use unoptimized: true for development

ISSUE: "Module not found" after npm install
FIX: npm install --save package-name

     Clear cache: rm -rf .next && npm run build
