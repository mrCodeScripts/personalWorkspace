=========================================================
|   THE "FULL-STACK" PROFESSIONAL RULES FOR FOLDERS:    |
=========================================================
1. Group by "Domain" (Parentheses): Use (dashboard), (auth), and (marketing) to separate the "Vibe" of the app. Each group can have its own layout.tsx.
2. Dynamic Routes ([id]): If you are building for a client who has many "Items" (Products, Projects, Documents), you use [id]/page.tsx.
  -> Professional Tip: Inside [id]/page.tsx, you use TanStack Query or a Server Action to fetch only that specific ID from Neon.
3. The "Shared" Folder: If a component is used in more than two places (like a Logo or a SubmitButton), it moves to components/shared/.
4. The "Feature" Folder: If you are building a specific complex feature (like a "Video Player"), give it its own folder: components/video-player/.

=========================================================
GOLDEN RULES OF NAMING FOLDERS
=========================================================
1. The "Big Three" Route Groups
  -> Stick to these three folders inside app/ and you’ll never be confused again:
    -> (marketing): Anything a person sees before they log in (Home, Pricing, About).
    -> (auth): Only the Login, Signup, and Forgot Password pages.
    -> (dashboard): Everything the user sees after they log in.
      Don't make a (user) folder. Just put /dashboard/profile or /dashboard/settings inside the dashboard group. It keeps your Sidebar logic much simpler.
2. The "Feature" Component Rule
  -> If you are building a SaaS for a client, don't just dump 50 files into components/. Group them by what they do:
    -> components/billing/: Stripe buttons, pricing cards, invoice tables.
    -> components/projects/: Project list, "Create Project" modal, Kanban board.
    -> components/layout/: Sidebar, Navbar, Mobile Menu.
3. Use "Next.js Conventions" to Name Files
  -> Stop trying to come up with creative names for files. Stick to the standard:
    -> page.tsx: The actual page content.
    -> layout.tsx: The wrapper (Sidebar/Nav) for that folder.
    -> loading.tsx: The skeleton screen while data is fetching (Next.js shows this automatically!).
    -> error.tsx: The fallback if the database crashes.
4. Pro Strategy: The "Address Book" Test
  -> If you can't find a file in 3 seconds, your structure is too complex.
  -> Too Complex: app/(dashboard)/(user)/settings/account/security/page.tsx
  -> Professional: app/(dashboard)/settings/page.tsx (Then just use "Tabs" inside that one page to show Account vs Security).

=================================
|   NESTED FILES CONVENTIONS    |
=================================
1. The Layout "Russian Doll" (Nesting)
  -> Root Layout (app/layout.tsx): This is global. It holds your <html>, <body>, and global providers (TanStack, Theme). It stays on the screen forever.
  -> Folder Layout (app/(dashboard)/layout.tsx): This only shows up when the user is in the dashboard. This is where you put your Sidebar and User Navbar.
  -> Sub-Folder Layout (app/(dashboard)/settings/layout.tsx): This only shows up on the settings pages. You could put a small "Settings Menu" (Account, Billing, Security) on the left side here.
  -> Why use this? When a user clicks from Dashboard -> Settings, the Sidebar doesn't re-render. It stays perfectly still, making the app feel like a desktop application.
2. The "Magic" Files (Loading & Error)
  -> This is how you beat the $500 competition.
  -> loading.tsx: If you drop this file into a folder, Next.js will automatically show it (usually a Skeleton screen) while your Neon Database is fetching data. You don't have to write if (isLoading) return <Spinner /> anymore.
  -> error.tsx: If the database crashes or the internet cuts out, Next.js catches the crash and shows this file instead of a "White Screen of Death." It usually has a "Try Again" button.
3. Stop using page-client.tsx
  -> Naming a file page-client.tsx is not an official Next.js convention; it’s a manual pattern some people use to stay organized.
  -> The Professional Way: Keep your page.tsx as a Server Component (no 'use client' at the top).
  -> If you need a "Button" or a "Form" that needs interactivity, you create a component in components/forms/MyForm.tsx (which is a Client Component) and import it into your page.tsx.
4. Example of a professional settings folder:
    app/
    └── (dashboard)/
        └── settings/
            ├── layout.tsx    # Horizontal sub-menu (Account, Billing)
            ├── loading.tsx   # Shimmer/Skeleton of the settings form
            ├── error.tsx     # "Oops, couldn't load settings"
            └── page.tsx      # The actual Account Form (Server Component)
